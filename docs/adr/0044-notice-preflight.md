# 0044 分发材料的完整缺口报告

日期：2026-10-30。状态：实施；结果见[预检说明](../notice-preflight.md)。

现有打包器在遇到第一个缺失许可文件时停止，无法一次看到整个 CLI/FFI SDK 依赖闭包的缺口。新增独立预检工具，复用相同的依赖闭包和根文件发现函数，列出所有包的版本、SPDX、文件哈希与问题；保留原打包器的拒绝行为与候选内容。

完成扫描与允许分发分开表达：报告 `overall=completed` 不代表材料通过；每个产品另有 `packager_notice_gate`，并明确没有执行法律评审。CI 保存报告，即使已知 macOS 材料仍被阻止；不能把 CI 成功解释为 macOS 候选可发布。

只做本地 Cargo 元数据与缓存文件检查，跨目标也不构建/执行二进制，不自动获取或拼接上游许可文本。后续补充文件需要精确来源、版本适用依据及版权材料，不通过放宽门槛解决。上游 issue 的讨论是调查依据，不作为自动授权。

测试覆盖正常/build/dev 边、循环、全部缺口、NOTICE 与 LICENSE 的区别、SPDX、非法文件名、内容上限、哈希、脱敏、源码变化及失败/中断作废。冻结源码后分别记录本机查询与原生 CI 查询；不把前者当作后者。无 Rust API、crate features、依赖、MIT、ABI 1、硬件 Schema 1 或 ZIP 格式变化。

回退可删除预检与 CI 步骤；共用的两个内部辅助函数可内联回打包器。既有缺失材料的拒绝规则必须保留。
