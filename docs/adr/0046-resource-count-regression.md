# 0046 C ABI 进程资源计数回归

日期：2026-10-30。状态：实施决定；原生结果另行归档。

内存曲线不能判断句柄或文件描述符是否被保留。新增独立 C 开发探针与 Python 验收工具，复用现有 release 共享库和本机编译器发现流程，不修改生产采集器或公共模型。

Windows 使用 `GetProcessHandleCount`；Linux 只枚举自身 `/proc/self/fd` 的编号并排除枚举用描述符；macOS 使用公开 POSIX `fcntl(F_GETFD)` 检查编号 0–65535。没有选择标为私有的 libproc 接口，也不把有限编号扫描称为完整资源枚举。最多 65536 项目录扫描、65536 次 fcntl 检查，错误直接失败，不猜测为零。各指标不是同一种资源，不跨平台比较数值。

校准独立打开/关闭 32 个事件句柄或 `/dev/null` 描述符，须精确增加 32 并回到原值。正常与阳性对照各执行 1000 次默认缓存 collect/free，第 100 次起每 100 次计数。热身后的十个点事前固定范围预算为 8；阳性对照在首点后保留 16 个资源，必须被同一分析器判为超预算，随后关闭。此预算用于有限回归，不承诺长期无泄漏。

工具保存各进程的完整有界观测、分析、提交/工作树、二进制哈希与编译器；子进程上限 210 秒。失败/中断作废旧报告，超预算的原始观测仍保留。C 采集检查 Buffer 并释放，不输出快照、路径或原始系统错误；库保留加载到进程结束。CI 不增加矩阵或新付费任务，报告加入现有三平台 artifact。

公共 API、ABI 1、硬件 Schema 1、features、依赖和 MIT 不变，新增报告是私有格式 1。回退可移除该工具、探针及 CI 步骤，保留历史证据。小时／天级运行、Mach port、线程、GDI/USER 对象及 allocator 分析不在本次范围内。
