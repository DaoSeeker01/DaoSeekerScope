# ADR 0035：Windows 候选包的 PE 检查

日期：2026-10-27。状态：实现，原生候选包与 CI 验收见[验证记录](../windows-pe-validation.md)。

## 要解决的问题

Windows CLI/SDK 已有校验和、隔离安装、C/Python 调用和回滚演练，但未记录实际二进制的架构、直接 DLL 依赖和版本声明。安装成功只能证明当前主机满足依赖，不能建立最低 Windows 版本保证。

## 选择与边界

在已有候选验收工具中增加只读 PE 检查，遵循微软 [PE 格式规范](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)。只实现当前 x86_64 PE32+ 候选所需的头部、节区、普通导入和 RVA 形式的延迟导入，不做通用 PE 加载器。使用 Python 标准库，不新增依赖、不调用系统加载器。

检查文件签名、机器类型、EXE/DLL 标志和子系统。CLI/C 消费者要求控制台 EXE；DLL 允许 GUI 或控制台子系统，不能把 DLL 的 GUI 声明误判为 GUI 应用。记录 OS 和子系统版本的头部声明。拒绝已知 MSVC 调试运行库；其他依赖只列出，不把名称列入报告等同于确认它属于 Windows、可再分发或在旧系统存在。

文件读取最多 64 MiB 加一个越界检测字节；节区最多 96；普通和延迟导入表分别最多 128 条描述符，去重后的合计依赖最多 128；模块名最多 260 字节。拒绝重叠节区、未映射地址、虚拟补零区域、截断数据、没有终止符的表、带路径或非 ASCII 的模块名。旧式 VA 延迟导入不在本候选契约中，明确失败，不能漏掉后继续通过。此子集检查不保证任意 PE 都被完整验证，也不代替操作系统加载器。

CLI 在创建安装目录前检查已校验的归档字节。SDK 同样先检查归档 DLL；每次安装、切换、回滚阶段在执行消费者前检查已安装 DLL 和新编译的 C EXE，要求 C EXE 直接导入 `daoseeker_scope_ffi.dll`。三个阶段记录的依赖与头部声明必须一致。验证报告新增 `pe_image`/`pe_images` 及检查次数；既有 ZIP 布局、格式 1/3、顶层进程数和失败报告规则保留。

不解析单个导入函数、API-set 映射、转发导出、传递依赖或运行期 LoadLibrary，不验证 Authenticode 签名，不建立最低 Windows 版本、VC Runtime 安装状态或无恶意代码的结论。报告中显式保留这些未验证状态。正式分发前仍需确定依赖来源及安装说明，并在选定最低系统环境实际运行。

## 验证与回退

纯字节测试覆盖损坏头部、架构、越界、表上限、路径、调试依赖与 SDK 绑定；测试不执行合成二进制。原生 Release CLI/SDK 继续走原有两槽位与 C/Python 门禁。Linux/macOS 只运行共享工具回归，不增加 Windows 依赖。

公共 Rust API、C ABI 1、硬件 JSON Schema 1、crate/feature/依赖和 MIT 不变。回退只需移除候选检查调用和对应新增报告字段，不改采集库或既有安装契约。
