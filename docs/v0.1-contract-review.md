# v0.1 发布前契约评审

当前为未发布的 0.1.0。本页把需要维护者确认的接口承诺集中列出；实施检查通过不等于正式发布获准。

## 本轮发现与修复

安装用 C 头文件原先没有说明共享库必须保持加载到进程结束。现与使用指南、ADR 和 Rust FFI 文档同步：任何采集调用后，包括失败或超时，都不得卸载或热重载。超时限制调用方等待，不能保证原生调用已停止；释放所有 Buffer 也不能证明 worker 已退出。

新增[契约基线](contracts/v0.1.json)和[自动检查](../scripts/check_contract.py)。它们检查清单、Schema 是否变化，以及 C/Rust 的真实布局是否都符合基线。具体决策和限制见 [ADR 0042](adr/0042-release-contract.md)。冻结提交 `52a68d0` 已通过本机与[三平台 CI 40807092742](https://github.com/DaoSeeker01/DaoSeekerScope/actions/runs/40807092742)；[证据索引](evidence/contract-ci-40807092742.json)保存四份原生契约报告和四份八包报告，包含本机记录。基线文件本身不作为运行证据。

## 待确认的承诺

| 项目 | v0.1 契约 | 检查与限制 |
|---|---|---|
| Rust 版本与包 | 八包统一 0.1.0，edition 2024，MSRV 1.96；MIT；默认功能以各包清单为准 | 清单基线、独立八包消费方；未承诺 Rust 1.0 级别 API 稳定性 |
| Rust API | 门面提供 `Hardware`、`collect`、动态刷新、取消与自定义 backend；公共模型不暴露平台依赖类型 | 编译、单元和独立消费方；没有完整自动 API 差异提取 |
| 状态与单位 | `Observed` 区分值、缺失状态、来源、时间与原因；字节、秒、0–100 百分比、摄氏度；Timestamp 为 Unix epoch 毫秒 | 不以默认零或空字符串伪造读取成功；总快照不是多 API 原子采样 |
| JSON | 硬件 Schema 1；未知对象属性忽略，未知枚举和非法 `Observed` 拒绝；输入与展开后的完整输出均不超过 1 MiB | 生成一致性、黄金样例、往返及负向测试；Schema 哈希变化只触发评审，不自动判断兼容性 |
| C ABI | 主版本 1，四个 `dsc_` 符号；库拥有 Buffer，调用方按 `len` 读取并用库释放；仅捕获可展开 panic | 固定错误码、C/Rust 原生布局、Miri/ASan、真实 C/Python 调用；无效指针、OOM/abort 不在可捕获保证内 |
| 线程与超时 | 不同 Buffer 可并行使用；资源争用可返回 Busy；后台调用可能在超时后继续；不支持共享库卸载 | 不对同一 Buffer 并发读取/释放；无 shutdown/drain，见[所有权契约](adr/0004-c-abi.md) |
| 隐私 | 敏感数据须显式请求且声明已获授权；仍受系统权限限制 | 默认脱敏及负向测试；调用方声明不是系统权限授予 |

### C 布局基线

仅冻结当前 CI 的 Windows x64、Linux x64 和 macOS ARM64。`dsc_options` 为 20 字节、对齐 4；五个 `uint32_t` 字段偏移依次为 0、4、8、12、16。`dsc_buffer` 为 24 字节、对齐 8；`data`、`len`、`token` 偏移为 0、8、16。字段顺序与[安装头文件](../bindings/daoseeker_scope.h)一致。其他目标必须先单独验证，不能套用这些数字。

状态码：0 成功，1 参数错误，2 平台不支持，3 超时，4 已取消，5 忙，6 backend 失败，7 资源上限，8 panic，9 Buffer 无效。线程局部错误文本已脱敏，有效期到同线程下一次 ABI 调用。

## 兼容性处理

0.1 系列补丁优先保持源码及行为兼容；需要破坏 Rust API 时使用 0.2 并提供迁移说明，参照 [Cargo 的 0.x 约定](https://doc.rust-lang.org/cargo/reference/semver.html)。C ABI 与硬件 Schema 独立编号：更改已有布局/所有权/错误语义须评审 ABI 主版本；增加旧 JSON 解码器无法接受的枚举值须协商 Schema 主版本，不能仅依赖 Rust `non_exhaustive`。

新增可默认字段仍需同步模型、Schema、黄金样例、隐私策略与旧消费方测试。基线变更必须说明为什么安全；不通过删除失败记录或放宽检查取得验收。
